# gen-docs

Плагин для Claude Code, который генерирует формальную документацию для информационных систем по российским стандартам ГОСТ.

Поддерживает четыре типа документов: руководство пользователя, руководство администратора, руководство оператора и техническое описание. Документы создаются в Markdown и конвертируются в DOCX через pandoc с оформлением по ГОСТ 2.105. Скриншоты интерфейса делаются автоматически через Playwright с поддержкой нескольких ролей пользователей.

## Установка

### Через маркетплейс Claude Code

Добавьте маркетплейс в `~/.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "gen-docs": {
      "source": {
        "source": "github",
        "repo": "borzov/gen-docs"
      }
    }
  }
}
```

Затем в Claude Code:

```
/plugin install gen-docs@gen-docs
```

### Ручная установка

```bash
git clone https://github.com/borzov/gen-docs.git
cp -R gen-docs/skills/gen-docs ~/.claude/skills/gen-docs
```

### Для разработки (симлинк)

```bash
git clone https://github.com/borzov/gen-docs.git ~/Develop/gen-docs
ln -s ~/Develop/gen-docs/skills/gen-docs ~/.claude/skills/gen-docs
```

## Использование

Откройте проект в Claude Code и введите:

```
/gen-docs
```

Скилл задаст несколько вопросов: какие документы генерировать, режим ГОСТ (строгий или облегчённый), путь к ТЗ, URL приложения для скриншотов. Если в приложении есть закрытые разделы, скилл попросит учётные данные для каждой роли (admin, user и т.д.) и сделает отдельный набор скриншотов для каждой из них. После этого запустит субагентов для анализа кода и спецификаций и сгенерирует документы.

Также можно просто написать в чате:

```
Сгенерируй руководство пользователя для этого проекта
```

### Что получится на выходе

```
docs/
├── generated/           # Markdown-исходники
│   ├── user-guide.md
│   ├── admin-guide.md
│   ├── operator-guide.md
│   └── technical-description.md
├── screenshots/         # Скриншоты Playwright — по одной папке на роль
│   ├── guest/
│   ├── admin/
│   ├── user/
│   └── manifest.json    # Все скриншоты с полями role и access
├── output/              # Готовые DOCX
│   ├── user_guide.docx
│   └── ...
└── meta.yaml            # Параметры для повторного запуска (добавьте в .gitignore — содержит пароли)
```

При повторном запуске скилл предложит использовать сохранённые параметры из `meta.yaml`.

## Как это работает

Скилл работает в четыре фазы:

1. Сбор параметров — интерактивные вопросы через Claude Code
2. Исследование — два субагента параллельно анализируют код и ТЗ, затем screenshotter-агент делает скриншоты: сначала гостевой проход для классификации роутов, потом параллельные сессии для каждой роли
3. Генерация — создание Markdown по шаблонам ГОСТ с подстановкой собранных данных
4. Конвертация — pandoc с эталонным reference.docx для стилей, затем постпроцессинг для таблиц, нумерации рисунков и отступов

## Режимы ГОСТ

Скилл поддерживает два режима оформления:

| | Строгий | Облегчённый |
|---|---|---|
| Шрифт | Times New Roman 14pt | Arial 12pt |
| Поля | 20/10/20/20 мм | 20/10/20/20 мм |
| Интервал | 1.5 | 1.15 |
| Титульный лист | Да, с реквизитами | Нет |
| Нумерация страниц | Внизу справа | Внизу справа |

Структура разделов в обоих режимах соответствует РД 50-34.698-90.

## Стандарты

| Стандарт | Что определяет |
|----------|----------------|
| РД 50-34.698-90 | Структура разделов документации |
| ГОСТ 34.201-89 | Виды и номенклатура документов |
| ГОСТ Р 59795-2021 | Требования к содержанию документов |
| ГОСТ 2.105-95 | Оформление: шрифты, поля, нумерация |

## Кастомизация стилей

Стили DOCX задаются через файлы `templates/reference-strict.docx` и `templates/reference-lite.docx`. Можно отредактировать их вручную в Word (изменить стили Heading 1–4, Normal, Caption) или пересоздать скриптом:

```bash
cd skills/gen-docs
python3 scripts/setup-reference-docx.py templates/
```

## Обновление

Через маркетплейс:

```
/plugin update gen-docs
```

При ручной установке — `git pull` и повторное копирование. При симлинке достаточно `git pull`.
