# Changelog

Все важные изменения в gostdocs.

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версионирование: [SemVer](https://semver.org/lang/ru/) — PATCH для исправлений, MINOR для функций, MAJOR для несовместимых изменений `meta.yaml`.

## [1.0.0] — 2026-04-25

Первый стабильный релиз. Скилл переработан под полноценную сборку пакета документации на информационную систему по ГОСТ — без ручной возни со скриншотами, нумерацией рисунков и подгонкой шрифтов.

### Что нового

- Шесть типов документов вместо четырёх: добавлены архитектурный документ и руководство по развёртыванию. Архитектурный документ собирает диаграммы компонентов, последовательность авторизации и потоки данных; руководство по развёртыванию даёт готовые `docker compose` и `curl`-команды с тестовыми учётными записями.
- Многоролевые скриншоты в параллельных сессиях. Каждая роль (гость, администратор, пользователь и любые произвольные) снимается в свою папку. Авторизация по умолчанию идёт через API; если API нет — плагин откатывается на форму. После логина выполняется проверка, что роль действительно вошла, а не вернулась обратно на страницу входа.
- Анализ интерфейса через vision-модель. Каждый PNG превращается в JSON: заголовок страницы, хлебные крошки, кнопки, фильтры, таблицы, модальные окна. По умолчанию работает Claude, опционально подключается gpt-4o от OpenAI. Если на скриншоте авторизованной роли всё равно вылезает форма логина — это попадает в отчёт как подозрительный кадр.
- Параллельный сбор знаний о проекте. Два субагента одновременно изучают код и техническое задание; отдельный адаптер извлекает схему БД (Prisma — нативно, остальные ORM — через `pg_dump --schema-only`); ещё один разбирает локальный OpenAPI или Swagger. Результаты кешируются по хешу содержимого, поэтому повторные запуски не тратят токены на одну и ту же работу.
- Автоопределение стека. PHP (Laravel, Yii2, Symfony), Python (Django, Flask, FastAPI), JVM (Spring Boot), Ruby on Rails, Go (Gin, Echo, Fiber), .NET (ASP.NET Core), Elixir (Phoenix), Node.js (Express, Fastify, NestJS), фронтенд (Next.js, Nuxt, SvelteKit, Remix, Astro, Angular, Vue, React) — в том числе в монорепах с раздельными `backend/` и `frontend/`.
- Mermaid-диаграммы. Архитектурная схема компонентов, последовательность авторизации, поток данных. Если `mmdc` не установлен или рендер упал — диаграмма попадает в документ текстовым блоком, а в отчёт пишется предупреждение.
- Многоязычный вывод. Русский и английский, общий глоссарий, рендер DOCX отдельно на каждый язык — без двойного прогона всей пайплайны.
- Пользовательские сценарии. Отдельный файл `journeys.yaml` со сквозными бизнес-процессами; в документ они попадают как "Шаг 1, Шаг 2, …" с привязанными скриншотами.
- Структурированный документ-модель. Раздел документа описывается JSON-структурой, рисунки и таблицы нумеруются автоматически по разделу ("Рисунок 2.3 — …"). Ручная нумерация и битые ссылки на рисунки больше невозможны.
- Отчёт по результату. `REPORT.md` суммирует покрытие по ролям, группирует одинаковые скриншоты по SHA-256, ловит пустые разделы и подозрительные кадры. `FINALIZATION_REPORT.md` отдельно проверяет готовый DOCX на остатки шаблонных плейсхолдеров перед сдачей.
- Два режима оформления ГОСТ. Строгий (Times New Roman 14, интервал 1.5, титульный лист) и облегчённый (Arial 12, интервал 1.15). В строгом режиме пустой обязательный раздел блокирует выпуск; в облегчённом — становится предупреждением.
- Самодостаточный sandbox. Плагин больше не требует, чтобы пользователь сам ставил Playwright или Chromium. При первом запуске всё нужное скачивается в `skills/gostdocs/node_modules/` и больше никогда не лезет в глобальное окружение.
- Автозаполнение метаданных. Версия, организация, ответственный, год берутся из git, package.json, composer.json, pyproject.toml — пользователю остаётся ответить только на действительно недостающие вопросы.
- Интерактивный сборщик `meta.yaml`. Скилл сам сканирует проект, формирует черновик конфига, задаёт точечные вопросы только по тому, что не смог определить. При повторном запуске переспрашивать не нужно.
- Пофазный запуск. Каждую стадию (precheck, research, plan-capture, capture, ui-inspection, generation, validation, finalisation) можно перезапустить отдельно через `--only`, переснять только одну роль через `--rerun-screenshots`, или пропустить съёмку целиком через `--skip-screenshots`.
- Безопасность по умолчанию. Пароли и API-ключи никогда не попадают в логи, `OPENAI_API_KEY` не эхо-логируется даже на ошибках провайдера, `meta.yaml` автоматически добавляется в `.gitignore` при первом сохранении.

### Несовместимые изменения

- Структура `meta.yaml` изменилась относительно 0.2 — роли вынесены в `auth.roles`, появились блоки `capture`, `pages`, `vision`, `metadata`. Старые конфиги мигрируются автоматически при первом запуске.
- Папка скриншотов теперь разделена по ролям: `docs/screenshots/<role>/<viewport>/<theme>/<locale>/`.

## [0.2.0] — 2026-04-14

Релиз про многоролевую съёмку и автоматическую авторизацию. До этого скилл умел делать скриншоты только публичных страниц от имени анонимного пользователя; теперь он может зайти в систему под несколькими ролями и снять каждую отдельно.

### Что нового

- Параллельные сессии Playwright под каждую роль. Скилл по очереди логинится администратором, пользователем и любыми другими указанными в конфиге ролями, и для каждой собирает свой набор скриншотов. Раскладка на диске разводится по папкам: `docs/screenshots/admin/`, `docs/screenshots/user/`, `docs/screenshots/guest/`.
- Автоопределение полей формы входа. Селекторы `username` / `password` / `submit` ищутся автоматически по типу инпутов и подписям; ручная конфигурация селекторов нужна только для нестандартных форм. Селекторы можно явно задать, если автоопределение промахивается.
- Гостевой обход роутов перед полноценной съёмкой. Скилл сначала проходит по всем страницам без авторизации и помечает, какие требуют логина, а какие публичные — это позволяет потом не тратить ресурсы на лишние сессии и не уводить публичные страницы в авторизованный набор.
- Конфигурируемая локаль вместо жёстко вшитого `ru-RU`.
- Защита от падения на пустых селекторах: если нужный элемент не найден, скилл пишет предупреждение в манифест, а не валится с ошибкой.
- Появилась инфраструктура автотестов на Jest — первые юнит-тесты для скриншоттера и адаптера авторизации.
- В `meta.yaml` появился блок `auth_roles` с учётными данными по ролям; пароли никогда не попадают в логи и в .gitignore-блокировку добавляется автоматически.
- В `SKILL.md` дополнен промпт screenshotter-агента: вопросы про авторизацию задаются отдельно от прочих, чтобы пароли не светились в общем потоке вопросов.

## [0.1.0] — 2026-04-09

Первый публичный релиз. Скилл умел сгенерировать четыре основных документа по ГОСТ для информационной системы из кода и небольшого набора параметров.

### Что было

- Четыре типа документов: руководство пользователя, руководство администратора, руководство оператора, техническое описание. Шаблоны под каждый — отдельные Markdown-файлы со структурой по РД 50-34.698-90.
- Два режима оформления. Строгий — с титульным листом, Times New Roman 14, межстрочным интервалом 1.5, оформление страницы по ГОСТ 2.105. Облегчённый — Arial 12 и интервал 1.15 без титульного листа, для внутренних целей.
- Линейный пайплайн из четырёх фаз: сбор параметров через интерактивный диалог, исследование кода и спецификаций двумя субагентами, генерация Markdown по шаблонам ГОСТ с подстановкой собранных данных, конвертация в DOCX через pandoc и reference.docx.
- Скриншот-автоматизация на Playwright для одного пользователя — обходит публичные страницы, делает PNG, складывает в `docs/screenshots/`.
- Reference-шаблоны DOCX (`reference-strict.docx`, `reference-lite.docx`) с настроенными стилями Heading 1–4, Normal, Caption.
- Постпроцессинг готового DOCX через python-docx: границы и отступы таблиц, шрифты по ГОСТ, нумерация рисунков с подписью "Рисунок N — …", корректная локализация поля оглавления, выравнивание TOC, замена эмодзи на текстовые эквиваленты, сквозная нумерация заголовков через `pandoc --number-sections`.
- Вспомогательный скрипт `setup-reference-docx.py` — пересобирает reference-шаблоны из шаблонных стилей, если потребовалось переоформить документ под изменённые требования.
